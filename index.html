Marginalia

May 2026 – now · 116 commits

An AI reading companion that brings your book highlights back when they matter.

Kindle highlights pile up and are never seen again. Marginalia imports them, finds the themes running across your whole library, and turns them into something you return to.

  • Imports Kindle clippings, removes duplicates, and groups books into AI-discovered themes
  • For each theme, writes a synthesis: why it resonates, where to go deeper, how to use it in practice
  • Book recommendations based on your reading patterns, plus a weekly email digest of highlights
  • Saves highlights from the web through a bookmarklet, and has an API that my AI assistants use to save quotes for me

How it was built
  • Reliability on free models. I set up a four-model fallback chain so the AI features keep working when a free model is rate-limited or retired.
  • Cached synthesis. Theme write-ups are generated once and stored, not regenerated on every visit. That keeps pages fast and the cost near zero.
  • Root-causing an outage. The free database kept pausing even though a keep-alive job was running. The agent's first theory was wrong. The real cause was how often the job pinged, and I fixed it based on the provider's documented rule.

How it was built
  • A platform, not one-offs. After the first game I had the agent write a playbook (accounts, schema conventions, scoring RPCs), so each new game starts from the same base.
  • Testing at volume. Math questions are generated fresh each time, so I had a test harness run 300 generations per topic and recompute every answer independently before shipping.
  • Product calls from playtesting. I set the mastery thresholds and the next-day review timing, and I collect feedback from my kids to decide what comes next.
  • Failures that announce themselves. A daily watchdog emails me if the backend keep-alive goes quiet, days before anything would break for the kids.

MoneyMaster

Jun – Jul 2026 · 31 commits

A "Duolingo for money" game for ages 11–14: run a small business, save, invest, and stay happy doing it.

Most money games reward hoarding. In MoneyMaster, spending on fun is necessary but has diminishing returns. Your score is the geometric mean of wealth and happiness, so both the miser and the splurger lose.

  • A 14-day season: you run a collectibles shop (the game's own "Moodlings" characters), set prices, and react to events
  • Market, sector and company news teach diversification hands-on: an ETF smooths out a single company's shock
  • Short teachable-moment cards appear exactly when a concept comes up in play

How it was built
  • Model the economy before writing code. I built the whole season as a live spreadsheet and simulated three player types. The balanced player wins, the hoarder and the splurger lose, and I confirmed that before any game code existed.
  • Design separate from mechanics. I made the brand and visual system with an AI design tool and kept the game-design doc as the source of truth for the rules.
  • Parallel agents. I split the build into waves for parallel agents (engine, content, backend, then screens), with a full play-through check after each wave.
